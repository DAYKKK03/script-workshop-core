# 定制化口播脚本写作规则

## 文档定位

本文档是定制化脚本功能的写作事实来源。它由用户提供的《口播脚本写作方法》提炼而来，供产品、Prompt 实现、测试和验收共同使用。运行时不得读取用户电脑上的原始 Markdown，也不得把整份原文或完整案例发送给 DeepSeek；运行时只使用压缩规则和短小的去标识化示例，并把最小必要规则固化为服务端常量。

## 设计理由

- 原始手册同时包含可复用的写作方法和仅对示例商家成立的事实，直接作为 Prompt 会让模型把案例数字、工艺或服务动作迁移到其他商家。
- 定制化脚本需要稳定控制字数、排版和语气，也必须把商家资料与创作表达分开：商家资料决定事实，写作规则只决定怎么说。
- 精简规则比每次附带完整手册更省 Token，更容易命中相同 Prompt 前缀缓存，也更便于测试和版本管理。

## 设计优点

- 统一自由需求、普通爆款选题和 Top 3 选题的输出质量。
- 用明确的本地校验规则降低模型自由发挥造成的格式漂移。
- 不重复发送 32KB 原文和完整范例，减少时延与调用成本。
- 事实边界可审计，示例中的未经验证说法不会成为全局规则。

## 一、输出硬规则

1. 只输出一条完整中文口播正文，不输出标题、分镜、时间轴、语气提示、结构分析或解释。
2. 前后端统一复用 `lib/custom-scripts/text.ts`：依次执行 NFC、CRLF/CR→LF 和边界 trim，边界 trim 去除 FEFF；正文只移除 Unicode `White_Space` 后按 Unicode code points 计数，内部 FEFF 不移除并计1。中文、英文、数字和标点各计1。页面创作目标约 **200—350** 字，Prompt 创作目标为 **240—300**；服务端内部安全范围为 **80—350**（含边界），80—199的完整安全口播先成为可恢复的内部fallback。
3. 使用自然口播排版，可按表达需要自由分段或换行。同一段可以包含多句，一句话也可以跨行，不限制单句长度或总行数；服务端不得按标点自动拆句。正文整体必须至少包含一个 Unicode 字母或数字，不能用纯空白或纯标点绕过长度校验。
4. 正文不得使用项目符号、编号、Markdown 标题、表情符号或占位符。
5. 默认不写点赞、关注、评论、私信、咨询或到店引导。
6. 仅当目标为 `conversion`，或用户明确要求行动引导时，结尾允许一个与内容直接相关的自然轻引导；不得同时要求多个动作。
7. 每条脚本只聚焦一个主题和一至两个核心卖点，不连续罗列商家资料。

### 字数自检与一次定向修复

- 首轮 Prompt 以240—300个 code points为创作目标，但不固定总行数或每行字数；开头写钩子，中段展开痛点、判断与商家资料已有事实，结尾用场景或选择逻辑自然收束。
- 服务端80—350内部安全范围、非口播内容、安全和事实校验是唯一硬通过标准。首次安全稿为80—199时，允许在剩余调用预算内做一次fresh `quality_enrichment`，争取达到产品目标200—350；Prompt不得暴露80底线，也不得为凑字编造事实。首次安全稿达到200—350时直接成功，不再强制二次调用。
- Prompt 必须明确服务端会去除全部 Unicode `White_Space`，汉字、数字、字母和标点各计1；模型返回前按同一口径自检，但不得返回 `charCount` 字段。
- 服务端只使用 `lib/custom-scripts/text.ts` 的计数结果。不得相信模型自报字数，不得通过服务端补写、删除或截断正文把不合格输出伪装成成功。
- `success.finalScript` 按固定顺序校验：JSON shape 与规范化 → 非空、整体字母或数字、列表/非口播内容 → 禁用表达、数字事实与 CTA → 与上一版重复 → 最后检查80—350总长度。该顺序不代表服务端已经全面验证全部非数字语义事实。
- 首轮正文少于80或超过350时，第二次 Prompt 只接收服务端实际计数和 `short|long` 方向，不携带首轮正文。短稿只补充与已有事实一致的场景、解释、感受和选择逻辑；长稿只删除重复修饰和次要表达。
- `quality_enrichment` 与非法JSON、空响应或领域校验失败后的安全重写都不得回灌首稿正文。价格、活动、地址、工艺、数据、资质、功效和服务事实仍只能来自商家资料。总 Provider 调用上限为2；`maxTokens=1600`、JSON response format、首轮温度0.75、修复温度0.5且关闭思考模式不变。
- 80—199首次安全稿必须先以processing内部 `quality_fallback` 持久化，再发起增强；processing公共API、第二次Prompt和日志不得返回或回灌fallback正文。若第二次Provider失败、返回非法输出或 `needs_profile`，或第二个安全稿比首次安全稿更差，任务必须使用fallback成功完成；若第二稿更好则选择第二稿。质量调使用40秒总预留，覆盖30秒租约恢复窗口、Worker轮询、数据库余量和至少5秒成功事务，整个任务只扣一次额度。
- 医疗事实按整句判断：明确诊断拒绝，真正的不确定表达、日常护理科普、预防提醒和咨询医生建议允许，但建议咨询医生不能洗白同句前面的明确诊断。商家高风险事实只有在“可信商家主体 + 能力动词 + 高风险事实”同时成立且最新资料支持时允许；可信主体包含固定门店称呼、服务端项目名称和去常见后缀后不少于2字的品牌名。普通“有人问、怎么选、如何判断、科普、了解”不是能力断言，项目名称不构成医疗或功效依据。
- 每次领域校验失败独立记录脱敏日志。长度日志只允许 `scriptLengthDirection=short|long`、`scriptLengthBucket=under_80|351_360|over_360` 与 `lineCountBucket=under_5|5_9|10_14|15_20|21_30|over_30`。行数只能记录范围桶，不能记录精确行数；不得记录精确字数、正文、Prompt或商家资料。最终失败日志可以保留最后一次白名单桶。
- `repairContext`仅在同一 Worker 进程的两次语义尝试间保存在内存。Worker若在两次尝试之间退出，新 Worker会按已持久化调用次数继续，但无法恢复未持久化的上次校验原因和精确计数；恢复后的剩余调用使用fresh路径。这是现有恢复边界，本阶段不新增数据库字段或Migration。

## 二、内容结构

### 开头

- 前三秒直接给出目标人群、具体场景、痛点、反差或悬念中的至少两项。
- 开头必须与用户需求或粘贴选题的核心方向一致。
- 禁止自我介绍、问候寒暄、主题报告和无信息感叹。

可选择一种钩子：

- 痛点：目标人群 + 具体问题 + 可能后果。
- 反差：常见认知 + 相反或不同的观察。
- 人群：具体人群 + 该人群的真实场景。
- 场景：可感知的生活画面 + 当前问题。
- 结果前置：有资料依据的结果 + 未立即揭晓的方法。
- 观点：常见选择 + 不同判断 + 理由暗示。
- 成本/避坑：资料明确的花费或损失 + 可执行建议。
- 好奇：真实反常现象 + 信息缺口。

### 中段

- 第一段内容直接回应开头，不重新介绍主题。
- 使用“问题 → 原因/判断 → 做法/体验”的自然推进；不能只堆形容词。
- 卖点必须与主题有因果关系，并转成动作、过程或消费场景。
- 一条脚本最多表达两个卖点；如资料较多，选择最贴近用户需求的内容。
- 专业表达优先说明可执行判断与适用边界，不用“专业、优质、领先”等词代替证据。

### 结尾

- 引流目标：以有用结论或开放问题收束；“下一条继续讲什么”的内容承诺与互动动作都只有用户明确要求时才允许。
- 信任目标：给出判断标准、适用边界或风险提醒，不主动推销。
- 转化目标：在中段已建立价值后，只给一个自然动作，例如咨询或到店了解；价格、赠品、名额和截止时间必须有商家资料依据。
- 结尾必须回应开头或给出下一步，禁止电视节目式收尾。

## 三、表达风格

### 自然聊天 `natural`

- 像朋友面对面说明，句子短、语气松、信息具体。
- 可以少量使用“其实、你想想、说白了”，但不得机械重复。
- 避免“值得注意的是、需要强调的是、众所周知”等书面腔。

### 专业可信 `professional`

- 通过真实流程、判断方法和局限体现专业，不通过自夸体现专业。
- 数字、标准、术语、资质和行业结论只有在商家资料明确提供时才能出现。
- 不得因为原始手册或示例出现某个技术数字、国家标准或行业结论，就用于当前商家。

### 情绪共鸣 `emotional`

- 用具体生活细节和克制感受帮助用户代入，不卖惨、不煽动焦虑。
- 情绪必须服务于问题与解决方法，不能只堆感叹词。

### 自动判断 `auto`

- 根据用户需求、选题目标和商家资料选择一种主风格。
- 自动判断不改变事实边界、字数和禁用表达规则。

## 四、商家事实边界

### 唯一商业事实来源

服务端按登录用户和 `projectId` 读取的商家最新 `profileText` 是唯一商业事实来源。用户需求或粘贴的爆款选题用于决定主题、受众、消费场景、钩子和表达方向，不能覆盖商家事实。官方选题头中的 `sourceProjectId`、`sourceType`、`sourceObjective` 只是来源校验元数据；服务端必须从原始文本解析并与对应请求字段交叉核对。`sourceObjective` 可初始化但不能锁定用户实际选择的 `objective`。来源项目必须属于当前用户并等于所选 `projectId`，可见项目名称不能替代该校验，也不能成为正文事实来源。

以下内容只有商家资料明确提供时才能写入：

- 店名、地址、服务区域、联系方式和营业时间。
- 价格、价格区间、折扣、赠品、名额、活动与截止时间。
- 产品、材料、工艺、制作步骤、服务流程和门店服务动作。
- 销量、案例数量、用户评价、经营年限、排名和对比数据。
- 资质、认证、获奖、国家/行业标准与技术数字。
- 功效、持续时间、结果、承诺、质保与售后条件。

服务端对脚本中的价格、比例、日期/时长、尺寸、温度和其他常见技术数字执行保守的“完整数字 + 相邻单位/符号”精确匹配。例如脚本中的 `30元` 只能由商家资料中的 `30元` 支持，`130元` 或 `30分钟` 均不能支持该事实。该校验只覆盖可稳定识别的数字事实；店名、服务动作、资质、功效和其他非数字事实仍依赖 Prompt 约束、本地禁用表达及阶段5的20组真实事实边界验收，不能仅因本地自动化测试通过就宣称零虚构。

### 可以创作性补充

- 不声称真实发生的通用消费场景。
- 与用户痛点匹配的克制情绪和口语过渡。
- 对已有卖点不改变含义的口语化表达。
- 不包含具体商业事实的一般性建议。
- 允许补充低风险通用行业知识，包括原因解释、判断标准、可执行方法、适用边界或风险提醒；一条脚本通常至少包含其中两类，避免只写空泛宣传。
- 不得把通用知识写成当前商家事实，不得暗示当前商家拥有未在资料中出现的设备、流程、资质、效果或服务行为。
- 不得生成医疗诊断、治疗方案、处方或效果保证；皮肤、美容等主题只能做一般护理和消费教育。
- 不得编造精确标准、技术参数或无依据数字；数字和标准只有商家资料明确提供且语境一致时才能写入。
- 服务端会保守拒绝“这是、确诊、诊断为、说明……”等指向玫瑰痤疮、皮炎、湿疹、感染或皮肤屏障受损的明确诊断表达；“可能、建议咨询医生”等非诊断一般提示允许。
- “我们、本店、本中心、门店、店里”等商家主体声称进口、专利、认证、资质、医生/专家或特定仪器设备时，相关高风险商家断言必须在最新商家资料中有依据；普通通用行业知识不因单独出现这些词就自动拒绝。

### 明确禁止的通用推断

- 不得把“E0 级”改写成“刷完当天能住”或其他健康/入住保证。
- 不得把某项美甲工艺改写成“多撑两周”等未经商家资料确认的效果。
- 不得凭空写“进店先倒热茶”“空调常年 26 度”“留一桶同色漆”等服务动作。
- 不得把案例里的“1.8 米、30 厘米、含水率 10%”等技术数字或“这是国标”迁移到当前脚本。
- 不得用确定语气攻击同行、可识别竞品或声称行业潜规则。

### 资料不足的处理

- 如果删除无依据事实后，仍可围绕已知产品、场景或真实卖点写满一条脚本，则删除该要求后继续生成。
- 如果用户要求的核心卖点、价格、活动、工艺、资质或效果没有资料依据，且删除后会改变主题，则返回 `needs_profile`，列出需要补充的事实，不生成正文。
- `missingFacts` 必须为1—5个互不重复的固定缺失资料码，只能来自下表；AI 不得返回自由文本、替用户补写答案、引用商家正文或泄露其他输入。
- 医疗、金融、法律等高风险主题缺少必要资质或依据时必须返回 `needs_profile`。

| `main_product` | 主营产品 |
| `core_selling_point` | 核心卖点 |
| `target_audience` | 目标人群 |
| `consumption_scene` | 消费场景 |
| `price` | 价格 |
| `promotion` | 活动 |
| `address_or_service_area` | 地址或服务区域 |

| `effect_claim` | 效果依据 |
| `production_process` | 生产或制作流程 |
| `materials_or_ingredients` | 材料、原料或成分 |

## 五、项目风格禁用表达

下列词语因不符合本项目的真实、接地气写作风格而禁止或限制。这里不宣称它们必然造成任何平台限流。

### 完全禁止

- 虚假承诺：保证有效、百分百满意、包治包好、无效退款（除非“退款”是资料中明确且合规的真实条款，仍不得作为效果保证）。
- 不可验证夸大：全网第一、行业领先、无人能比、史上最。
- 空泛套话：家人们谁懂啊、绝绝子、yyds、闭眼冲。
- 虚假紧迫：错过再等一年、最后一天、仅此一次。
- 乞讨互动：求点赞、求关注、帮忙转发、三连走起。
- 电视腔：观众朋友们、各位网友、今天我们来聊一聊、感谢观看。

### 尽量少用

- 空泛形容词：专业、靠谱、优质、高端、精致。
- 说明书连接词：首先、其次、最后、总之、综上所述。
- 无信息感叹：太好了、真的绝了、太牛了。
- 万能结尾：希望对大家有帮助、关注我了解更多。

## 六、换一版规则

- 沿用当前商家、需求、目标和风格。
- 上一版正文仅用于差异校验，不得成为新的商家事实来源。
- 新版本必须更换开头钩子和主要表达角度，不能只替换同义词或调整行序。
- 服务端在开篇差异之外，还会校验整篇正文复用：去空白标点后的整篇字符二元组 Dice 相似度达到82%即视为与上一版过于相似；多行正文另保留相同行复用达到70%的检查，因此单段自然口播也不能通过轻微改字绕过。
- 仍须满足80—350内部安全范围、基础非口播内容、事实边界和 CTA 规则。自然口播可以自由分段或使用长句，排版不作为拒绝原因；用户创作目标仍约为200—350字。

## 七、能力边界

本规则能够控制单条约一分钟中文口播的结构、字数、排版、风格、卖点数量、CTA 和商业事实使用方式；适用于自由需求、普通爆款选题和 Top 3 选题输入。

## 八、限制说明

- 本规则不能证明某条脚本会爆款、获得特定播放量或带来转化。
- 当前不接入实时热点、外部标准库或事实检索，无法验证商家资料外的行业结论。
- 商家资料仍是一个大文本框，AI 对模糊事实的判断必须通过 staging 用例验证；仅靠 Prompt 不能保证零误判。
- 原始手册中的完整案例只用于提炼写作方法，不是可以跨商家复用的事实库。
- 首稿本身未达到80—350硬安全范围时，连续两次不合格仍整体失败、不展示半成品且不扣成功额度；但首次安全稿80—199触发的可选质量尝试失败时，必须回退首次安全稿成功完成。
